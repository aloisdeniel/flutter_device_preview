Flutter · binding-level simulation

Any device.
Zero widgets.

Device Preview simulates screen metrics, safe areas, locale, brightness, text scale and accessibility at the binding level — your widget tree stays completely untouched. Drive it from a DevTools panel or three lines of Dart.

Get started pub.dev ↗
$ flutter pub add device_preview
Architecture

One line. Three seams.
No wrapper widget.

FIG. 01 — INTERPOSITION

Previous generations of device preview tooling wrapped your app in widgets — a simulated MediaQuery here, a themed control panel there. It worked, but your widget tree was never quite your widget tree.

Device Preview 3 moves the whole simulation below the widget layer. A custom WidgetsBinding hands the framework a wrapped FlutterView and PlatformDispatcher, so every MediaQuery, every layout pass, every pointer event and every locale lookup sees the simulated device — because the framework itself does.

When simulation is off (the release default), the binding returns the host objects directly. Zero interposition, zero cost, zero behavioral difference.

main.dart
void main() {
  DevicePreviewBinding.ensureInitialized();
  runApp(const MyApp());  // completely unmodified
}

The dispatcher seam

BindingBase.platformDispatcher

A wrapping PlatformDispatcher + FlutterView pair answers every framework read — size, pixel ratio, padding, locales, brightness, text scale — with the simulated value, and delegates everything with engine side effects to the host. Explicit member-by-member delegation, no noSuchMethod: if a future SDK adds a member, the package fails loudly at compile time instead of silently at runtime.

The fit matrix

createViewConfigurationFor

The root render view lays out at the simulated logical size and paints through a scale-to-fit matrix — centered, letterboxed, never upscaled. Pointer events are rewritten through the exact inverse, so taps, drags and hover land where they should. Semantics geometry rides the same transform for free.

The service protocol

ext.device_preview.*

A small, versioned VM-service protocol exposes state, presets and mutations, and posts events on every change. It's what the DevTools extension speaks — and it's plain JSON, so CI scripts and editor plugins can speak it too. Tree-shaken out of release builds entirely.

FIG. 03 — EXTENSION

Nothing is drawn over your app. The control panel lives where developer tooling belongs — in Flutter DevTools, as a first-class extension that appears automatically for any app depending on device_preview.

Pick a preset, rotate it, drag the text scale, flip brightness, reorder locales, toggle accessibility flags — the running app updates live over the VM service. Change simulation from Dart code instead and the panel follows, echo-free, thanks to per-request IDs.

Hot restart proof: the app forgets, the panel doesn't. With Keep across restarts enabled, the extension re-pushes your simulation the moment the app comes back.

Or drive it from Dart

LST. 04 — CONTROLLER
anywhere.dart — the controller API
final c = DevicePreviewBinding.controller;

// full preset, orientation included
await c.applyPreset(DevicePresets.iPhone16Pro);
await c.setOrientation(Orientation.landscape);

// partial overrides, merged over the real device
await c.update((s) => s.copyWith(
  textScaleFactor: 2.0,
  platformBrightness: Brightness.dark,
));

// back to reality
await c.reset();
widget_test.dart — simulated widget tests
void main() {
  final binding =
      TestDevicePreviewBinding.ensureInitialized();

  testWidgets('lays out like an iPhone SE', (tester) async {
    await binding.devicePreview!
        .applyPreset(DevicePresets.iPhoneSe3);
    await tester.pumpWidget(const MyApp());
    // MediaQuery: 375×667 @2x, SE safe areas.
  });
}

The same machinery is a public mixin — DevicePreviewBindingMixin — so it layers onto flutter_test and integration_test bindings. The test-binding recipe is ~30 lines, lives in your own test/ folder, and keeps flutter_test out of your app's dependency graph. Golden tests across a device matrix, without a device in sight.
